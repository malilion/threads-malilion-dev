pstack 裡面有幾個很有意思的 Skill：
 /how
回答：
這個系統現在是怎麼運作的？
去追 Runtime、Code Flow、不同 Service 之間的關係。

/why
回答：
當初為什麼要這樣設計？

不只看 Code，還可能去找：
Git History
PR Comments
Linear
Notion
Slack
Datadog
Sentry
Analytics

因為：
Code 告訴你 What。
但不一定告訴你：
Why。

還有一個我很喜歡：
/teach
叫 Agent 把剛才研究的東西，
重新用人類聽得懂的方式教你。
例如：
> 為什麼你選這個做法？
> 另一個方案不行嗎？
> Trade-off 是什麼？

這其實不只是讓「人類理解 Agent」。
Agent 在解釋的過程中，
自己也會重新檢查：
到底有沒有真的讀過 Code、資料與歷史紀錄。
